# 투두 직접 조작·처리 기록·소스 연결

2026-10-30. 포트폴리오 `#project/todo`에 직접 등록·시간 배치·완료하는 브라우저 실습을 추가한다. 기존 oddk 서비스는 별도 앱 링크로 유지한다.

ALPEN 작업 블록: A=원본 대응 확인/조작·저장/3D·소스/실패·모바일 검사/공개 배포, L=구현50분·검증20분 블록 추정, P=수정·통합 여유30%, E=동일 ID·저장 성공 경계·실제 실행 소스 우선, N=아래 검증·배포 결과 갱신. 예산이며 실측 시간은 아니다.

## 사용 흐름과 데이터 경계

1. 제목을 입력해 등록한다. 같은 제목의 시간 미설정 미완료 항목은 중복 등록하지 않는다.
2. 목록에서 같은 항목을 선택하고 시작 시각·작업·여유를 정한다. 계획 = 작업 + 포함된 여유, 합계2~240분이다. 이 실습은 당일 종료만 지원한다.
3. 목록 체크박스로 완료/완료 취소한다. ID와 기존 시간은 유지하고 진행 중인 시간표에 포함되는지만 바꾼다.

`portfolio:todo-lab:v1` 키만 사용한다. 실제 localStorage 저장 성공 뒤 React 목록이 바뀐다. 다른 탭의 최신 값과 비교해 오래된 상태 덮어쓰기를 거부한다. 저장 실패는 기존 목록과 입력을 유지하며 성공 프레임을 만들지 않는다. 손상 자료는 자동 덮어쓰지 않고 사용자가 전용 체험 자료 초기화를 선택할 수 있다.

처리는 브라우저 이벤트에서 실제로 실행하고, 그때 기록한 저장 전·후 스냅샷을 재생한다. 단계·소스·3D 요소를 선택하는 관찰 동작은 저장을 반복하지 않는다. 일반 서버 요청·Redis·DB 처리가 있는 것처럼 표시하지 않는다. oddk 본 앱 계정·원본 저장소에는 접근하지 않는다.

## 원본과 실행 코드

기본 `체험 실행 코드`는 이 페이지가 실제 호출한 함수를 보여준다. `oddk 기준 구현`은 독립 앱의 대응 코드이며 전체 앱 실행으로 표시하지 않는다.

| 단계 | 실제 실행 코드 | oddk 기준 |
|---|---|---|
| 입력/화면 반영 | `TodoWorkbench.runAction` | `addTask` / `toggleDone` / 편집 규칙 |
| 입력·상태 검증 | `prepareTodoAction` | `parseEditorSchedule` / 등록·완료 규칙 |
| 브라우저 커밋 | `commitTodoState` | 원본 앱 `save` |
| 시간표 겹침·열 | 동결된 `timeline.ts`를 바이트 그대로 복사해 `layoutTimeline` 호출 | 같은 함수 원본 |

원본 리비전은 `af0728e7a562bbc78471edc41a088afc93d66be6`을 유지한다. 실행 함수는 안정된 포트폴리오 커밋에서 행과 파일 SHA-256을 추출한다. 원본 시간표 파일의 전체 SHA-256도 검사한다.

## 확인 상태

- 모델8그룹: 등록·중복·시간 보존·당일 종료·겹침/연속·완료/취소·저장 실패·오래된 탭·손상 보존/분리 초기화 통과.
- 브라우저: 등록 → 배치 → 완료/취소 → 새로고침, 단계별 소스/스냅샷, 실패 시 입력 보존, 320~1800px, 동작 줄이기·WebGL 대체와 모바일 패널 이동을 검사한다.
- 실제 OAuth·계정 동기화·서버 I/O·실물 휴대기기는 이번 실습 검증 범위 밖이다.
