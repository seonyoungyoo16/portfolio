# 로그인·로그인 유지 체험

프로젝트 카드와 `#project/login` 경로로 연결한다. 게시판·채팅의 기존 경로와 체험을 유지한다.

## 실제 구현과 Pages의 역할

독립 구현은 [springboot-login-lab](https://github.com/seonyoungyoo16/springboot-login-lab)의 Spring Boot 3.5·Spring Security·Spring Session·Redis·PostgreSQL이다. 실제 HTTPS 요청, DB 상태, Redis 키·TTL, 독립 브라우저 프로필과 장애 경계를 검증했다. 소스 기준 커밋은 `a2bf485592c2d59d34c5e109a8b9bc839713f138`이다.

GitHub Pages 체험은 같은 처리 규칙을 설명하는 브라우저 시뮬레이션이다. 실제 인증 쿠키를 발급하거나 운영 인증 서버에 요청하지 않는다. 모든 화면에 이 범위를 명시하고 독립 실험실의 실행 방법·설계·검증 결과를 연결한다. 임의의 아이디·비밀번호는 서버로 전송하거나 브라우저 저장소에 기록하지 않는다. 기기 A·B는 별도 브라우저 프로필을 설명하며 서버 A·B는 같은 공유 세션 저장소를 사용한다.

## 체험과 소스 연결

- 로그인: 계정·IP 요청 제한 → BCrypt 검증 → DB PREPARING → Redis 저장 → DB ACTIVE → 성공 쿠키.
- 보호 요청: 공유 세션 조회 → DB 활성·폐기·버전 확인 → 유휴 TTL 갱신. 절대 종료는 고정한다.
- 로그인 유지: 세션 식별자가 없는 재방문 → 행 잠금 → 현재 토큰 검증과 세대 교체 → 새 세션 활성화. 유지 종료는 고정한다.
- 동시 복원: 첫 요청 200, 같은 이전 토큰의 늦은 요청 409. 유예 이후 재사용은 401, 성공 쿠키는 유지한다.
- 기기 폐기: 현재 기기·전체 기기, 최근 비밀번호 재확인, 만료된 세션의 유지 자격정보 폐기.
- 장애: 저장소 연결 확인 불가, ACTIVE 직전 실패, 유지 복원 응답 유실, 폐기 후 Redis 정리 실패, 옛 Redis 키 복구와 DB 차단, 정리 재시도.
- 가상 시계: +1분·30분·8시간·14일. 실제 백엔드의 만료 테스트는 실제 경과 시간으로 확인한다.

처리 단계마다 스냅샷을 보관해 PREPARING과 Redis 저장 시점에도 브라우저 성공 쿠키가 없는 것을 보여준다. 재생·일시 정지·단계 선택·다음 단계·마지막 이동을 지원한다. 소스는 정해진 Git 커밋의 30개 코드 조각을 12개 파일에서 추출하며 파일·행·원본 링크를 표시한다. 화면 관찰은 만료를 연장하지 않는다.

체험 모델은 정책을 설명하기 위한 축약이다. 요청 제한의 원자성·CSRF 실제 거부·실제 프로세스 재시작·브라우저 재실행·쿠키 보안 속성은 독립 프로젝트의 실제 검증 근거로 안내한다.

## 검증

- `npm run test:login`: 상태 전이 18개 시나리오. 발급 경계, 만료, 교체, 재사용, 여러 기기 폐기, 실제 소스와 같은 실패 처리 규칙을 확인한다.
- `npm run verify:login-source`: 30개 코드 조각과 파일 해시 12개, 실제 정책 값, 독립 검증 결과 연결.
- `npm run test:login-browser`: 실제 브라우저 18개 묶음. 로그인부터 폐기·장애까지 버튼으로 실행하고 소스·데이터·1440/1800/768/390px 화면·모바일 패널·실행 오류와 기존 게시판·채팅 경로를 확인한다.
- 기존 게시판·채팅의 상태 모델과 채팅 소스 검증도 수행한다.
- 독립 백엔드 API·저장소 20건과 브라우저 41건은 Pages 시뮬레이션 검사와 별도 근거이다.

브라우저 결과와 캡처는 [login-verification](login-verification)에 기록한다. `local`은 개발 서버, `published`는 공개 Pages URL의 결과다. 공개 배포 후 기록은 배포 결과와 함께 갱신한다.
