# 사용자 행동과 처리 흐름 연결

사용자 요청: 왼쪽을 일반 사용자가 순서대로 조작할 수 있게 통일하고, 행동과 3D 경로·상태·실제 소스 매핑을 함께 검증한다.

ALPEN: A=공통 사용자 체험·프로젝트별 단계·경로/소스 감사·브라우저 검증·배포, L=구현 50분/검증 15분 블록, P=통합 여유 30%, E=기본 행동과 소스 대응 우선, N=아래 결과 갱신. 계획 시간이며 실제 실행 시간과 구분한다.

## 행동과 소스가 대응하는 기준

`방금 한 행동`은 사용자의 의도를 유지하고 그 아래 현재 프레임만 이동한다. 이전 행동을 관찰하는 중 다음 요청의 기기·서버를 바꿔도 이전 행동의 주체와 소스는 바뀌지 않는다. 로그인 유지 없는 재방문과 잘못된 비밀번호는 성공처럼 표시하지 않는다.

인증 경로는 노드 이름을 추측해 잇지 않는다. `auth-trace.ts`에서 각 소스의 명시적인 경계를 선언한다. DB·Redis 왕복은 서버에서 출발해 저장소에 도착하고 돌아오며, 서버 내부 검증은 서버만 강조한다. 브라우저 닫기·메일 링크 열기·실습 환경 변경은 로컬 요소만 강조하며 HTTP 패킷을 만들지 않는다. 현재 이동 중인 연결만 주황색이고 다중 경로는 길이에 따라 순차 이동한다. 장애 지점은 실패로 표시하고 도착한 성공처럼 재생하지 않는다.

로그인 PREPARING 추출 범위를 73행, OIDC 시작/콜백을 92/120행으로 늘려 실제 INSERT·리다이렉트·코드 교환이 보이게 했다. 독립 백엔드의 고정 커밋은 그대로다. 소스 역할은 실제 구현·설정·브라우저 동작·관찰 로그로 구분한다. [소스 계약 7그룹](user-journey-verification/source-contract.json), [13개 로컬 분기](user-journey-verification/interaction-source.json)를 검증했다.

채팅의 `결과 바로 보기`도 저장·전달·ACK·자동 읽음 단계를 모두 실행한다. 단계를 건너뛰어 저장을 생략하거나 같은 메시지를 두 번 만드는 빠른 완료는 허용하지 않는다. 가입의 사용자 이메일과 현재 실습 상태를 동기화했고, 주문 생성과 실제 결제 확정도 구분한다.

## 검증 근거와 범위

[새 체험 12그룹](user-journey-verification/local/browser.json)은 기본 순서·오류 복구·실제 렌더링 연결·소스 링크·SSO 명시적 연결·부분/전액 취소·오프라인 채팅 복구·모드 전환·모바일 이동을 포함한다. 기존 브라우저 91그룹은 `직접 실험하기`로 진입해 이전 세부 실험을 그대로 검사한다. Chromium 320/390/768/1440/1800px 뷰포트 검사다. 공개 화면은 처리 규칙을 재현하는 브라우저 시뮬레이션이며, 이번 UI 변경에서 실제 백엔드 I/O를 재실행하지 않았다. 기존 실제 Spring Boot·Redis·DB 검증 근거는 별도 고정 링크로 유지한다.
